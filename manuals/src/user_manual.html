01
Introduction

Welcome to Serialine

Serialine prints a unique serial number on every product on your line, straight from your Excel or CSV file. Each product that passes the sensor gets the next serial, in order, and every print is recorded.

One serial per product

Printing is triggered by your line sensor, so a serial only goes on a product that is actually there.

No duplicates

The printer checks the serial sequence itself and never prints the same serial twice.

Works from your own files

Use the Excel or CSV list you already have. No database or special software needed.

Full traceability

A print log records every serial with its date and time, ready for your batch records.

Safe restarts

After a stop, a power cut or a closed window, Serialine continues from the first unprinted serial.

Controlled reprints

A batch is printed again only after explicit confirmation, and the original log is kept.

Any batch size

Print 5,000, 50,000 or more unique serials in one continuous run – no splitting files.

Keeps up with your line

Serialine feeds the printer ahead of production, so the line never waits for data.

Simple

Double-click, choose the file, press ENTER. No installation and no technical knowledge needed – your UMS technician sets everything up.

02
Overview

How it works

Serialine sends your serials to the printer; your line sensor decides when each one is printed.

1
Serial file
Your list of unique serials in Excel or CSV
2
Serialine
Reads the file, sends serials over the network
3
Printer queue
Always kept topped up with the next serials
4
Line sensor
Each product triggers exactly one print
5
Product
Receives the next serial in the list
6
Print log
Records serial, date and time

The printer queue is a rolling buffer: it holds the next 255 serials, and Serialine refills it continuously as products are printed. A batch can contain any number of serials – 5,000, 50,000 or more – in one production run. When the last serial is printed, Serialine stops the printer automatically.

04
Data

Preparing your serial file

One file = one batch. Save it in the Serialine folder with a name that identifies the batch, e.g. Batch2026-041.xlsx.

  1. Serials in column A of the first sheet, starting in cell A1.
  2. No heading row. Anything in A1 is printed as the first serial.
  3. One serial per row, printed top to bottom. Empty rows are skipped. There is no limit on the number of rows.
  4. Every serial must be unique. Serialine refuses a file that contains a serial twice.
  5. Serials must fit the print field on your printer – ask UMS for the maximum length.

Example – first sheet

A
1AV2026000001
2AV2026000002
3AV2026000003
4AV2026000004

Leading zeros are kept: 000123 prints as 000123.

05
Daily procedure

Printing a batch

Starting a batch takes under a minute.

Before you start

  • Printer on, correct job loaded, jet running
  • Printer printing stopped ("Ready for print start")
  • Serial file saved in the Serialine folder

Start the batch

  1. Double-click Serialine (Serialine.exe) in the Serialine folder.
  2. Serialine lists the files in the folder. Type the number of your batch file and press ENTER.
  3. Check the line Printing records 1..N. N must match the number of serials in your batch.
  4. Serialine loads the first serials into the printer and shows Press ENTER to start printing. Press ENTER.
  5. Run the line. Each product gets the next serial; the screen shows [PRINTED] with the serial.
  6. After the last serial the printer stops automatically and the screen shows [SUCCESS]. Press ENTER to close.

06
When things change

Stops, restarts and reprints

Serialine always continues from the first unprinted serial. No serial is skipped or printed twice.

The printer stops during a batch

An error, or someone presses Stop.

  1. The screen shows [STOPPED] Printing stopped after record X.
  2. Fix the cause and acknowledge any message on the printer.
  3. Check the last product: it should carry serial number X in your list.
  4. When Serialine shows Press ENTER to start printing, press ENTER. Printing continues from serial X+1.

Serialine was closed, or the computer restarted

  1. Stop printing on the printer.
  2. Start Serialine and choose the same file.
  3. Serialine reads the print log and continues from the first unprinted serial.

Printing a completed batch again

First

Remove the products from the first print that carry these serials, so no serial exists twice.

  1. Start Serialine and choose the same file.
  2. At Print it again? (y/N) type y and press ENTER.
  3. Type YES in capitals and press ENTER to confirm. The original log is kept and a new log is started.
Good to know

A product that reaches the sensor right after the last serial, before the printer has stopped, receives a blank print. Remove it from the line.

07
Traceability

Your print log

For every batch, Serialine writes a log in the Serialine folder named after the batch file: Batch2026-041.xlsx → Batch2026-041_log.csv. It opens in Excel.

timestamprecordserial
2026-10-06T08:14:021AV2026000001
2026-10-06T08:14:032AV2026000002
2026-10-06T08:14:033AV2026000003
  • Keep every log with the batch records. Serialine also uses it to continue after a stop.
  • Do not edit, rename or delete a log while its batch is not finished.
  • After a reprint, the earlier log is kept as <batch>_log_before_reprint_<date>_<time>.csv.
  • Back up the Serialine folder regularly, for example to a network drive.
